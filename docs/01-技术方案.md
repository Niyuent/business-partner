# 01 · 技术方案与项目结构

## 一、已确认的技术决策

| 项 | 决策 |
|---|---|
| 仓库形态 | **单仓 npm workspaces**（`server` / `web`），后续可无损拆分 |
| 第一阶段范围 | **只做管理后台**（主体 + 附属）；H5 最后做最简版 3 页：积分余额、积分兑换、我的卡包 |
| 券码生成方式 | **预生成券码**（`coupon_codes` 批量生成，发放时一次性绑定实例） |
| 积分有效期粒度 | **每笔积分批次 + N 个月，FIFO 扣减** |
| 登录 | 账号密码（JWT），微信授权后置 |
| 通知 | 站内信，微信订阅消息后置 |
| 报表导出 | 前端 CSV，后端 Excel 后置 |

## 二、技术栈

| 层 | 选型 |
|---|---|
| 前端 Admin | Vue 3.5 + Vite 6 + TypeScript + Element Plus + Pinia + Vue Router 4 + Axios |
| 图表 | ECharts 5 + vue-echarts |
| Mock | 自研 **Axios Adapter Mock**（`VITE_USE_MOCK` 开关，业务代码零侵入） |
| 后端 | NestJS 10 + TypeScript + Prisma 5 + MySQL 8 |
| 认证 | JWT（Access 2h / Refresh 7d）+ 自建 RBAC Guard |
| 校验 / 文档 | class-validator + `@nestjs/swagger` |
| 定时任务 | `@nestjs/schedule`（积分过期、券过期、报表生成） |

## 四、开发顺序（MVP Sprint）

| 阶段 | 内容 |
|---|---|
| **S0 脚手架** | workspaces 初始化；NestJS 骨架（响应/异常/Swagger/Prisma）；Vite+EP 骨架（布局/路由/request/登录页）；Prisma schema + 迁移 SQL + seed |
| **S1 商家与权限** | admin_users/角色/权限码；JWT 登录；入驻审核；商家启用暂停；授权管理与授权记录；操作日志 |
| **S2 代金券** | 模板 CRUD + 上下架；券码生成；发放（含 H1/H2 校验）；核销页（输码）；核销记录（含 H4/H5） |
| **S3 积分与订单** | 积分规则；消费送积分；兑换扣积分；FIFO 与过期任务；积分流水；订单 + 异常订单（H3） |
| **S4 采购对账报表** | 采购记录；对账账单；报表中心 6 张 + CSV 导出；工作台图表 |
| **S5 附属侧 + 通知 + 主体用户管理** | 附属 8 页；门店变更申请与审核；站内信；`/main/users` 只读页（H6 隔离） |
| **S6 H5 简版 + 联调** | H5 三页；关 mock 走真实接口；边界用例回归；部署脚本 |

每阶段交付顺序：Prisma schema → seed → service/controller + Swagger → 前端 api → mock handler → 页面 → 自测。

## 四·附 MVP 范围外（v2 计划）

以下需求**MVP 明确不做**，已从阶段内的收口待办中移出，统一挂到这里按 v2 排期：

| 需求 | MVP 行为 | v2 计划 |
|---|---|---|
| 券适用范围「指定商家」（`applyScope=SPECIFIED_MERCHANTS`） | 建模板 / 编辑 → 400 `APPLY_SCOPE_UNSUPPORTED`；核销走到该分支 → 409 `APPLY_SCOPE_UNSUPPORTED`（不放行适用范围未知的券） | 新增 `coupon_template_merchants` 关联表；发券时按商家归属展开门店；核销时按「券实例归属商家 → 门店列表」校验，覆盖后续新增门店；同时提供迁移工具把历史「指定门店」数据升级为商家维度 |

MVP 支持：`ALL_STORES`（全部门店，含后续新增门店）、`SPECIFIED_STORES`（指定门店）。详见 docs/03 §6.1「已知限制」。

## 五、Mock 边界

**S0–S5 前端可独立运行（mock）**：登录（本地账号表）、工作台/报表图表、所有列表详情（内存 DB + localStorage）、券码核销状态机、积分兑换与流水、CSV 导出、图片上传（base64）、站内信。

**后置接真实服务**：微信授权登录、`wx.scanCode` 扫码核销、OSS 文件上传、短信/订阅消息推送、后端 Excel 流式导出、定时任务（积分过期 01:00 / 券过期 01:10 / 月结报表）、Redis 幂等与分布式锁。

**切换方式**：S1.4 起 **Mock 已整体移除**（`src/mock/**` 删除，`request.ts` 不再挂载 adapter），所有请求一律走真实后端；`VITE_PROXY_TARGET` 仅用于本地 dev server 的代理目标（默认走网关 `http://localhost:80`，与生产链路一致）。

## 六、安全边界声明

前端隐藏菜单/按钮仅为体验优化。所有权限、数据隔离、业务规则校验**必须在后端 Guard/Service 层实现**，详见 `docs/04-业务规则与验收用例.md`。
