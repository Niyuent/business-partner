# 02 · 数据库设计（Prisma / MySQL 8）

## 〇、通用约定

- 主键：`Int` 自增无符号（避免 BigInt 在 JSON 序列化上的坑）；金额 `Decimal(12,2)`；积分 `Int`。
- 审计字段：`createdAt / updatedAt`（`@updatedAt`）。
- 状态字段使用 **Prisma enum**（物理映射 MySQL `ENUM`），枚举名即语义，避免魔法数字。
- 软删除仅用于 `coupon_templates`（`status = VOID`），不引入全局 `deletedAt`。
- **所有业务规则约束以上层 Service + 数据库唯一索引双重保证为准**，见「四、约束清单」。

### 关键约定：`point_rules.merchantId = 0`
`0` 表示**平台级默认规则**。读取逻辑：先取 `merchantId = 当前主体商家` 的有效规则，取不到则回落到 `merchantId = 0`。
只有 `PLATFORM_ADMIN` 可修改 `merchantId = 0` 的记录；主体商家只能配置自己 `merchantId` 的规则。

### 关键约定：券码绑定方向（单向）
- **只保留 `coupon_codes.instanceId` 作为唯一绑定方向**，删除 `coupon_instances.codeId`。
- `coupon_instances.code` 为**冗余只读展示字段**，在「发放事务」中与 `coupon_codes.instanceId` 一并写入，事后禁止修改。
- 唯一绑定入口：`bindCodeToInstance(tx, codeId, instanceId)`（S2 实现），事务内校验 `code.status = UNISSUED` 且 `instanceId IS NULL`。

> S1 只做「登录时一次性返回权限码数组」的简化映射；完整 RBAC 动态配置后置。

## 四、约束清单（数据库 + Service 双重保证）

| 约束 | 数据库 | Service/Guard |
|---|---|---|
| H1 券创建者必须是主体 | `creatorMerchantId` 索引 | 创建/更新接口断言 `type=MAIN` |
| H2 附属发券授权校验 | — | `AuthorizationService.assertCanIssue()` 四重校验 |
| H3 一单一券 | `orders.couponInstanceId` **UNIQUE** | 写入前查重 |
| H4 核销幂等 | `redemption_records UNIQUE(couponInstanceId, status)` | 事务 + `Idempotency-Key` |
| H5 核销前置校验 | — | `RedemptionService.verify()` 返回原因码 |
| H6 数据隔离 | — | `MerchantScopeGuard` 强制注入 `merchantId/storeId` |
| H7 订单不含采购 | `orders.orderType` 仅两值 | 采购走 `purchase_records` |
| 券码单向绑定 | `couponCodes.instanceId` **UNIQUE** | 仅发放事务内绑定一次 |
| 积分批次 FIFO | `index(expireAt, remainingAmount)` | 消耗按 `expireAt ASC` 扣减 |
| 积分账户并发 | `pointAccounts.version` | 乐观锁更新 |
