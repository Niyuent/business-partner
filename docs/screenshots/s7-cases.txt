================================================================================
后端：SSE 接入 Notification
================================================================================
触发点：NotificationService.send() —— 事务内 createMany 后按 sendBatchId 查回新建行，
        **事务提交后**调用 SseService.broadcast（避免回滚后前端已收到）。
推送数据：event=notification:new，data={ id, title, content, level, type, createdAt }
鉴权与隔离：
  · ticket 一次性（60s），`GET /sse/notifications?ticket=` 用 ticket 换 identity(userId/merchantId/storeId/userType)
  · MERCHANT → target { merchantId } → 该商家管理员 + 其所有门店店员
  · STORE    → target { merchantId(门店所属商家), storeId } → **仅该门店店员** + 该商家管理员
  · SseTarget 新增 storeId 维度；match 用 `storeId == null` 兼容 JWT 未带该字段的管理员
心跳：沿用 S1 的 30s `: ping`（SSE_HEARTBEAT_MS 可配），nginx 侧 proxy_buffering off + 3600s 超时已就绪。

**修复的 S1 遗留缺陷**：`GET /sse/notifications` 未加 `@Public()`，被全局 JwtAuthGuard 拦成 **401**
（EventSource 无法带 Authorization 头，鉴权本应由 ticket 承担）。加 `@Public()` 后恢复 200。

后端用例 tmp-s7-cases.mjs（16/0）：
  ✅ ticket 换流 200 + text/event-stream
  ✅ connected 握手
  ✅ MERCHANT 2 推送 → sub01 收到，**延迟 22ms**，payload 字段齐全
  ✅ 同商家门店店员 clerk01 也收到（商家级）
  ✅ STORE 101 推送 → clerk01 收到（**43ms**）、sub01（商家管理员）收到
  ✅ 跨商家隔离：sub02（merchant 3）两条都收不到
  ✅ 无效 ticket / 不带 ticket → 403
  ✅ 在线连接数 ≥ 3

前端：铃铛接 SSE（移除轮询）
================================================================================
api/notification.ts 新增：
  · SSE_NOTIFICATION_NEW='notification:new' / SSE_CONNECTED='connected'
  · notificationSse.ticket() → POST /sse/ticket
  · notificationSse.connect(ticket) → new EventSource(`${VITE_API_BASE}/sse/notifications?ticket=...`)
stores/notification.ts 新增 increment(n)：收到推送直接 +1，不再回拉接口。

NotificationBell.vue：
  · **删除** 60s setInterval 轮询与 visibilitychange 补刷（连同 `// TODO(sse)` 注释）
  · onMounted：store 未加载则 refresh 一次（首屏），然后 connectSse()
  · 监听 notification:new → store.increment() + 铃铛抖动 600ms + 右下角 ElNotification（5s，可点击跳通知中心）
  · onerror：**主动 close 再自建**（EventSource 自带重连会把已消费的一次性 ticket 重放 → 必然 403），
    指数退避 3s→6s→12s→24s→48s→60s 封顶；connected 握手成功后重置为 3s
  · onUnmounted：disposed 标记 + close + 清两个定时器（防卸载后仍排队重连）
