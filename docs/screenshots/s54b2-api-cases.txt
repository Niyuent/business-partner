本次发现并修复的 bug（S5.4-B1 遗留，被本批用例抓到）
================================================================================
文件：server/src/modules/notification/notification.service.ts  markRead()

  修复前：return { ...this.withReadState(row), alreadyRead: count === 0 };
  修复后：return this.withReadState(row);

现象：首次标记已读返回 alreadyRead=false，重复标记反而返回 true —— 语义完全颠倒。
      （count 是 createMany skipDuplicates 实际新建行数：首标=1、重标=0。）
根因：withReadState 已在 create 之后重查 read 记录、本身就是权威口径，却又被 count===0 覆盖。
影响：前端列表/详情靠手动置 true 所以 UI 看不出问题，但 API 契约错误（第三方接入会踩坑）。
验证：修复后用例「PATCH read → alreadyRead=true」通过；重复标记仍 200（幂等保持）。
