任务 1：清理测试脚本交叉脏数据
================================================================================
问题：历史 S3.x 脚本用「直接 SQL 造订单」的方式准备数据，其中越权用例**故意**使用
      「A 商家的 merchantId + B 商家的 storeId」错配组合（例：tmp-s31 F12 的
      `mkOrder('ORD-S31-X2', 1093, 2, 201, 10)`），跑完不清理，导致列表里出现
      「商户与门店不匹配」的脏数据。

处理（三层）：
1. **回归前置 seed**（原有）：每次 npm run regression 先重置到固定主键基线。
2. **回归收尾 seed**（本次新增）：scripts/regression.mjs 用 try/finally 包住跑测流程，
   无论成功 / 失败 / 中途中断，跑完都再 seed 一次 → 环境一定回到干净基线。
3. **单脚本自清理**（本次新增）：tmp-s31-cases.mjs 末尾删除自己造的 ORD-S31-* 订单
   （只删未被 coupon_instances 引用的行，避免外键报错）。
4. 新增 `npm run db:reset`：单跑某个脚本后一键恢复干净环境。

验证（收尾 seed 后实测）：
  orders 总数 = 4（seed 基线）
  错配行（o.merchantId <> s.merchantId）= 0 行  ✅
  ORD-S3* / TEST* 残留 = 0 行                 ✅

任务 2：S4.3 报表回归脚本（tmp-s43-cases.mjs，26 条全过）
================================================================================
覆盖：
- 6 张报表 GET /reports/{merchant-onboarding,orders-summary,coupon-summary,
  points-summary,store-settlement,authorization-logs} → 200 且返回结构逐字段断言
- 6 张报表 CSV 导出 → 200 + Content-Type: text/csv + **UTF-8 BOM（EF BB BF）** + 表头正确
- 数据隔离（附属口径为「收敛到本商家」而非 403，脚本按实际语义断言）：
  · 附属 merchant-onboarding summary.total = 1（主体视角 = 4）
  · 附属 orders-summary byMerchant 只有自己
  · 附属 authorization-logs 每行都与自己相关
  · **附属显式传别家 merchantId=3 → 仍只返回自己（不越权）**
  · 另一个附属只看自己；店员报表收敛到本店
- 权限与校验：
  · 店员无 report:export → 403
  · 附属有 report:export → 200
  · 非法报表 key → 404（路由层拦截）
  · 非法 key 的导出 → 400（DTO @IsIn）
  · 未登录 → 401；pageSize=201 → 400

踩坑记录（值得留存）：
  用 `res.text()` 判断 BOM 会**假阴性** —— WHATWG fetch 的 UTF-8 解码会自动剥离 BOM，
  服务端明明发了 EF BB BF 前端也看不到。改用 `arrayBuffer()` 判前 3 字节。
