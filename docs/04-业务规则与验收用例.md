# 04 · 业务规则硬约束、验收用例与 Seed 数据要求

> 本文件是**开发与验收的唯一依据**。凡标记为「硬约束」的规则，必须在**后端**强制落地，
> 前端隐藏按钮 / 隐藏菜单只作为体验优化，**不作为安全边界**。

---

## 一、业务硬约束（后端强制）

### H1 代金券模板创建者必须是主体商家
- `POST /coupon-templates` 与 `PUT /coupon-templates/:id` 强制校验：
  `creatorMerchantId` 对应 `merchants.type = MAIN(1)`，否则抛 `BizException(403, COUPON_CREATOR_NOT_MAIN)`。
- 数据库层：`coupon_templates.creator_merchant_id` 建立索引，seed/constraint 在 Service 层断言。
- 推论：**所有代金券只能由主体商家创建**；附属商家后台不提供「创建代金券」入口（S2 落地 `coupon:create` 权限码）。

### H2 附属商家发券三重校验（`POST /coupon-instances/issue`）
按顺序校验，任一失败立即返回：

| 序号 | 校验 | 失败响应 |
|---|---|---|
| 1 | 调用方是附属商家且存在 `status=ENABLED` 的 `merchant_authorizations` 记录 | `403 SUB_MERCHANT_NOT_AUTHORIZED`（未授权直接 403，不进入后续逻辑） |
| 2 | 目标模板 `ownerType = MAIN_COUPON(1)` | `403 SUB_MERCHANT_CAN_ONLY_ISSUE_MAIN_COUPON`（发附属商家券一律拒绝） |
| 3 | 若授权记录 `templateScope = SPECIFIED`，模板必须在 `merchant_authorization_templates` 内 | `403 TEMPLATE_NOT_IN_AUTHORIZED_SCOPE` |
| 4 | 模板 `status = PUBLISHED(2)` 且库存充足、在有效期内 | `400 TEMPLATE_NOT_AVAILABLE` |

- 前端对应：未授权附属商家**看不到**「发放主体券」菜单（`v-permission` + 路由守卫），且接口层二次拦截。

### H3 一单只能用一张券（不可叠加）
- 数据库：`orders.coupon_instance_id` **唯一索引**（多数订单为 NULL，MySQL 唯一索引允许多个 NULL，符合预期）。
- 后端：任何写 `orders.coupon_instance_id` 的入口（录单、补录、核销关联）先查
  `orders where coupon_instance_id = ?`，命中则抛 `400 ORDER_COUPON_ALREADY_USED`。
- 核销前校验：订单已存在券 → 拒绝。

### H4 核销幂等
- 数据库：`redemption_records` 上 `UNIQUE (coupon_instance_id, status)`。
  效果：同一券**不可能同时存在两条 `status=SUCCESS` 记录**；冲正后 status 变更为新值，允许再次核销。
- 接口层：
  - `POST /redemptions` 必须开启**数据库事务**（Prisma `$transaction`）。
  - 支持幂等键：`Idempotency-Key` 请求头（或 body `requestId`），同一 key 重复提交返回首次结果，不重复扣减。
  - 事务内：`SELECT ... FOR UPDATE` 语义（Prisma 事务隔离级别 `Serializable`/`RepeatableRead`）锁定券实例。

### H5 核销前置校验（失败必须返回明确原因码）
`POST /redemptions/verify` 与 `POST /redemptions` 均执行，返回 `{ canRedeem, reasonCode, reasonText }`：

| 校验项 | 失败原因码 |
|---|---|
| 券码不存在 | `CODE_NOT_FOUND` |
| 券码未绑定实例（未发放） | `CODE_NOT_ISSUED` |
| 券不属于当前用户 | `COUPON_NOT_BELONG_TO_USER` |
| 券已使用 | `COUPON_ALREADY_USED` |
| 券已过期 | `COUPON_EXPIRED` |
| 券已冻结 | `COUPON_FROZEN` |
| 券模板已下架/作废 | `TEMPLATE_NOT_PUBLISHED` |
| 适用范围不符（门店/商家不在 `apply_scope`） | `STORE_NOT_IN_SCOPE` |
| 不满足门槛金额 | `THRESHOLD_NOT_MET` |
| 订单已使用其他券 | `ORDER_COUPON_ALREADY_USED` |
| 核销门店不属于当前商家 | `STORE_NOT_OWNED`（数据隔离，见 H6） |

### H6 附属商家数据隔离（MerchantScopeGuard）
- 所有 `/sub/**` 接口（以及订单、核销、采购、对账等「资源型」接口）统一走 `MerchantScopeGuard`。
- Guard 从 **JWT 中的 `merchantId` / `storeId`** 注入过滤条件，**忽略并覆盖**前端传入的 `merchantId`/`storeId`。
- Service 层查询必须携带 scope 条件，禁止出现「不携带 merchantId 的全表查询」。
- 主体商家账号放行全平台；平台管理员放行全部。

### H7 订单与采购职责分离
- `orders.order_type` **仅**保留：`CONSUME(1) 线下消费`、`EXCHANGE(2) 积分兑换`。
- **删除**采购类型；券采购一律走 `purchase_records` 与 `settlement_reports`。
- 采购**不产生积分**、**不产生券实例**（券实例由采购后发放产生），资金结算线下完成，系统只记录 `settle_status`。

## 三、积分有效期（按批次 + FIFO）

- 每笔 `EARN` 流水即一个**批次**，带 `expire_at = 获取时间 + point_rules.points_valid_months 个月`。
- 消耗时按 `expire_at ASC` 依次扣减 `remaining_amount`（FIFO，优先消耗最早过期的积分）。
- 定时任务（`tasks/points/expire`，每日 01:00）：
  扫描 `remaining_amount > 0 AND expire_at < now()` → 生成 `EXPIRE` 流水（负数）→ 归零 `remaining_amount` → 扣减 `point_accounts.balance`、累加 `total_expired`。
- 账户级 `balance` 与流水求和必须一致，提供 `/tasks/points/check` 自检接口（S3 落地）。

## 五、验收用例（S2–S6 逐条回归）

| # | 用例 | 期望结果 | 覆盖约束 |
|---|---|---|---|
| A1 | 未授权附属商家（sub02）登录后 | 侧边栏**无**「发放主体券」菜单；直接调用 `POST /coupon-instances/issue` 返回 **403** | H2-1 |
| A2 | 已授权附属商家（sub01）进入发券页 | 模板下拉**仅出现**主体券 T1、T2；T3 与附属券 T4 不可选；强制传 T3/T4 返回 **403** | H2-2/H2-3 |

| A5 | 过期积分自动清零 | 执行 `/tasks/points/expire` 后，过期批次 `remaining_amount=0`，生成 EXPIRE 流水，`balance` 相应减少 | 三 |
| A6 | 附属商家查看订单 | sub01 仅能看到 S-101 / S-102 订单；传 `merchantId=SUB-02` 无效（被 Guard 覆盖） | H6 |
| A7 | 核销幂等 | 同一券码并发/重复提交 2 次，仅生成 1 条 SUCCESS 核销记录 | H4 |
| A8 | 适用范围不符 | 仅适用 S-101 的券在 S-201 核销 → `STORE_NOT_IN_SCOPE` | H5 |
| A9 | 主体创建券时伪造 creator | 用 sub01 token 调 `POST /coupon-templates` → `403 COUPON_CREATOR_NOT_MAIN` | H1 |
| A10 | 采购不进 orders | 采购记录只出现在 `purchase_records`，`orders` 中无 `order_type=采购` 记录 | H7 |

## 六、错误码规范

后端统一抛出 `BizException(code, message)`，HTTP 状态码语义：

| HTTP | 场景 |
|---|---|
| 400 | 参数校验失败、业务规则不满足（原因码在 `data.reasonCode`） |
| 401 | 未登录 / Token 失效 |
| 403 | 权限不足、未授权、越权访问（H1/H2/H6） |
| 404 | 资源不存在 |
| 409 | 幂等冲突 / 并发冲突（H3/H4） |
| 500 | 未捕获异常 |

响应体：`{ code: number, message: string, data: any, traceId: string }`
